# ТЗ: Геофильтр в каталоге («ближайший магазин ко мне»)

## 1. Цель

Дать пользователю одной кнопкой найти **ближайшие к нему секонд-хенды** —
без ввода адреса, без лишних шагов. Это особенно полезно туристу или человеку
не из своего района.

---

## 2. Реализуемость и ограничения

### 2.1. Telegram умеет
- Принимать геопозицию пользователя через `KeyboardButton(request_location=True)` —
  reply-клавиатура. Приходит `message.location` с `latitude`/`longitude`.
- Принимать «живую» (live) геопозицию — обновляется автоматически. Для нашего
  кейса избыточно, **берём одноразовую**.

### 2.2. Telegram НЕ умеет
- Запросить геопозицию через **inline-кнопку**. Сейчас весь бот живёт на inline.
  Значит на момент запроса геопозиции придётся показать reply-клавиатуру
  (`📍 Поделиться геопозицией` / `✖️ Отмена`), а после получения координат —
  убрать её через `ReplyKeyboardRemove()` и продолжить как обычно.

### 2.3. Координаты магазинов
В таблице `shops` сейчас только `address` (текст). Чтобы сравнивать расстояние,
нужны `latitude` / `longitude` каждого магазина. Два варианта получить:

| Вариант | Плюсы | Минусы |
|---|---|---|
| **(a) Ручной ввод админом** | Без внешних зависимостей. Точность ~10 м. | Один раз пройтись по всем ~50 магазинам. |
| **(b) Геокодинг по адресу** (Яндекс/OSM Nominatim) | Заполняется автоматически. | Нужен API-ключ (Яндекс) или соблюдение rate-limit (OSM). Точность зависит от качества адресов. |

**Рекомендация:** (a). Магазинов мало, админ это сделает за полчаса
через ту же reply-кнопку «📍 Прислать координаты» в SA-карточке магазина.
(b) можно добавить второй итерацией, если рутина задушит.

### 2.4. Расчёт расстояния
Haversine — простая формула, считается в Python в одну функцию (4 строки).
50 магазинов × 1 пользовательский запрос — мгновенно, кэш не нужен.

### 2.5. Приватность
- Координаты пользователя **в БД не сохраняем**. Держим в памяти процесса
  (как поисковую строку — `_user_location: dict[int, tuple[float, float]]`).
- Сбрасывается автоматически при рестарте бота / нажатии «✖️ Сбросить» / выходе в меню.
- В UI явно говорим: «Я не сохраняю геопозицию, спрошу её снова при следующем запуске.»

## 3. Что добавляем

### 3.1. БД

Добавляем в `shops`:
- `latitude  REAL` (nullable)
- `longitude REAL` (nullable)

Миграция: новый файл `data/migrations/00X_shops_geo.sql`.

### 3.2. Админка (SA-панель → карточка магазина)

В существующий экран редактирования магазина добавить блок:

```
📍 Координаты
   <если заданы> 44.6166, 33.5254
   <если нет>    — не заданы

[ 📍 Установить координаты ]   ← открывает reply-кнопку «Поделиться геопозицией магазина»
[ ✖️ Очистить координаты ]      ← если уже заданы
```

Это reply-keyboard вход с `request_location=True`. Админ либо сам стоит у магазина,
либо ставит метку на карте Telegram перед отправкой.

### 3.3. Каталог: новый фильтр / сортировка

Где живёт кнопка — **в меню «↕ Сортировка»** новым пунктом:

```
↕ Сортировка
[ • По названию • ]
[ По дню завоза ]
[ По цене сегодня ]
[ 📍 Ближайшие ко мне ]   ← НОВОЕ
[ ◀️ Назад ]
```

Логика:
- Юзер тапает `📍 Ближайшие ко мне`.
- Если координаты пользователя **уже есть в памяти** — сразу пересортировать каталог.
- Если нет — отправить новое сообщение с reply-клавиатурой:
  ```
  📍 Чтобы показать ближайшие магазины, поделись геопозицией.
  Я её не сохраняю — спрошу снова при следующем входе.

  [ 📍 Поделиться геопозицией ]   ← reply, request_location=True
  [ ✖️ Отмена ]
  ```
- Юзер делится → принимаем `message.location.latitude/longitude`, сохраняем в `_user_location`,
  убираем reply-клавиатуру (`ReplyKeyboardRemove`), рендерим каталог с `sort=near_me`.

### 3.4. Дисплей расстояния

В шапке каталога при активной геосортировке:
```
🛍 Каталог секонд-хендов
Найдено: 12 · 📍 Сортировка по близости
```

В тексте кнопки магазина (когда `near_me` активен):
```
🚚 ⭐ Megahand: Победы, 12  ·  ~0.8 км
```

В карточке магазина (опционально, всегда когда оба знают координаты):
```
📍 Севастополь, ул. Победы, 12  ·  ~0.8 км от тебя
```

### 3.5. Магазины без координат
- Из сортировки `📍 Ближайшие` они **исключаются** (а не падают в конец).
  Иначе картина «ближайший за 999 км» — мусор.
- В шапке: `Найдено: 12 (3 без координат — скрыты)`.
- В обычной сортировке (`по названию` / `по цене` / `по завозу`) — отображаются как обычно.

### 5.2. Хранение пользовательской геопозиции
```python
# handlers/catalog.py
_user_location: dict[int, tuple[float, float]] = {}  # user_id -> (lat, lon)
```
Сбрасывается:
- кнопкой `✖️ Сбросить` в каталоге;
- при выходе в меню — **нет** (сохраняется на сессию);
- автоматически после рестарта бота.

### 5.3. Haversine
```python
import math
EARTH_RADIUS_KM = 6371.0
def haversine_km(lat1, lon1, lat2, lon2) -> float:
    p1, p2 = math.radians(lat1), math.radians(lat2)
    dp = math.radians(lat2 - lat1)
    dl = math.radians(lon2 - lon1)
    a = math.sin(dp/2)**2 + math.cos(p1)*math.cos(p2)*math.sin(dl/2)**2
    return EARTH_RADIUS_KM * 2 * math.asin(math.sqrt(a))
```

### 5.4. Форматирование расстояния
- `< 1 км` → `~250 м`
- `1..10 км` → `~1.2 км` (одна цифра после запятой)
- `≥ 10 км` → `~12 км` (без дробной части)

### 5.5. Что НЕ делаем (out of scope)
- ❌ Live-локация (постоянное обновление). Для секонд-хендов избыточно.
- ❌ Радиусный фильтр («только в 3 км»). Сортировка по близости + сама ясная картина — лучше.
- ❌ Карта внутри бота (показ всех магазинов на карте). Telegram такое не умеет нативно.
- ❌ Маршрут / навигация. Кнопка «Открыть в Картах» в карточке — возможно, но отдельной задачей.

## 6. Открытые вопросы

1. **Координаты — ручной ввод админом или геокодинг по адресу?**
   Рекомендация: ручной (вариант (a) из §2.3).

2. **Кнопка `📍 Ближайшие` живёт в подэкране «↕ Сортировка» или вынести наверх?**
   Рекомендация: в Сортировке — главный экран и так плотный, см. /docs/CATALOG_FILTER_TZ.md.

3. **Магазины без координат при геосортировке — скрывать (рекомендуется) или показывать в конце с пометкой «координаты неизвестны»?**

4. **Показывать ли расстояние «~0.8 км от тебя» в карточке магазина всегда (когда координаты обеих сторон известны) или только когда активна геосортировка?**

5. **Сбрасывать геопозицию из памяти автоматически через N минут?** Сейчас предлагаю — нет, держим до явного `✖️ Сбросить` или рестарта бота.

6. **Нужна ли кнопка «Открыть в Яндекс.Картах»** на карточке магазина (генерирует deeplink из координат)? Это маленькая, но приятная фича.

7. **Магазины без координат в админке** — нужен ли SA-репорт «12 магазинов без координат — заполни»?
