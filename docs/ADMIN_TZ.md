# ТЗ: Админка и Супер-Админка для бота `@secondhandtwo_bot`

Документ описывает полную функциональность админ-панелей. Пишется как «делаем сразу всё».
Источник истины: Telegram inline-кнопки + слэш-команды. Все операции дублируются: и кнопкой, и командой.

---

## 1. Роли и права

| Роль | Ключевые права |
|---|---|
| **user** | пользоваться ботом: каталог, подписки, настройки уведомлений |
| **admin** | управлять только закреплёнными за ним магазинами и связанными сущностями |
| **super_admin** | всё, что admin + управление всеми магазинами, админами, конфигом, БД, аудитом, режимами обслуживания |

Хранение:
- `admins(tg_id PK, role enum('admin','super_admin'), added_by, added_at, note)`
- `shop_assignments(shop_id, admin_tg_id, assigned_by, assigned_at, PRIMARY KEY (shop_id, admin_tg_id))`

Загрузка ролей: при старте бота `super_admin` подтягиваются из `.env` (`SUPER_ADMIN_IDS=...`), обычные `admin` — добавляются супер-админами через панель и им же назначается набор магазинов.

Проверка в коде:
- `IsAdmin` — любая роль
- `IsSuperAdmin` — только супер
- `IsAdminForShop(shop_id)` — `super_admin` всегда True; `admin` — только если есть запись в `shop_assignments`
- `IsAdminForChain(chain_name)` — аналогично, но через JOIN c `shops`

### 1.1 Scoped-модель для обычного админа

Обычный админ — «менеджер своих магазинов». Он:
- видит **только** свои магазины в списках, карточках, статистике, рассылках, парсерах, фидбеке;
- редактирует только их (имя/адрес/описание/фото/цикл/anchor);
- получает уведомления только по своим магазинам (новый фидбек, ошибки парсера и т.п.);
- может рассылать сообщения только аудитории «подписчики моих магазинов» (или их подмножества);
- не видит ни списка других админов, ни магазинов, которые ему не назначены, ни глобальных настроек.

Что **запрещено** обычному админу:
- создавать/удалять магазины (только супер);
- менять `chain_name` магазина (это меняет принадлежность сети — только супер);
- ставить anchor сразу всей сети (`set_chain_arrival`) — только супер;
- видеть/редактировать чужие назначения, админов, конфиг, БД, аудит;
- рассылка по «всем активным» — только по подписчикам своих магазинов.

Что **разрешено** супер-админу дополнительно:
- создавать магазин и сразу назначать его одному или нескольким админам;
- переназначать магазин между админами;
- видеть и редактировать всё.

Все списки и репозитории, отдающие магазины, имеют параметр `actor_tg_id` либо принимают опциональный `scope_shop_ids: list[int] | None`. Когда вызывает `super_admin` — `scope_shop_ids=None` (без ограничений). Когда `admin` — список из `shop_assignments`.

Helper: `await visible_shop_ids(actor_tg_id) -> list[int] | None` (None = все).

## 2. Главная админ-панель (роль `admin`)

Открывается по кнопке «🛠 Админка» в главном меню (есть только у админов) и по `/admin`.

```
🛠 Админ-панель

[ 🆕 Магазины          ]  ← раздел
[ 📦 Завозы и циклы    ]
[ 👥 Пользователи      ]
[ 📣 Рассылки          ]
[ 💬 Фидбек            ]
[ 🚚 Парсеры           ]
[ 📊 Статистика        ]
[ ⚙️ Настройки бота    ]   ← только super_admin
[ 🛡 Супер-админ        ]   ← только super_admin
[ 🏠 В меню            ]
```

Все экраны редактируют сообщение (`edit_text`), а не плодят новые. Все длинные списки — пагинацией по 10 элементов. Везде `← Назад` к родительскому экрану.

## 3. Раздел «Магазины»

> **Scope:** обычный админ видит только закреплённые за ним магазины. Супер-админ видит все.

### 3.1 Список магазинов
- Заголовок: для admin — «Мои магазины (N)», для super — «Все магазины (N)».
- Сортировка: «По названию», «По сети», «По дате последнего завоза», «Только неактивные».
- Поиск по подстроке: `🔍 Найти` → ввод текста → результат (внутри scope).
- Карточка из списка: открывается экран «Магазин #ID» (см. 3.2).
- Bulk-режим: «Выбрать несколько» → чекбоксы → действия: `Сделать неактивными`, `Активировать`, `Удалить` (последнее — только супер).

### 3.2 Карточка магазина (admin view)
Показывает все поля и инлайн-кнопки управления:

```
🛍 Секонд №1 на Восставших  (id=4)
[Megahand]  ✅ активен
📍 Восставших, 18
🗓 Цикл: 14 дней   |   Anchor: 22.04.2026
👀 Подписчиков: 37
📅 Следующий завоз: 06.05.2026
─────────────────────────
Описание: ...

[ ✏️ Имя ] [ ✏️ Адрес ] [ ✏️ Описание ]
[ ✏️ Сеть* ] [ ✏️ Цикл ] [ ✏️ Anchor ]
[ 📷 Фото магазина ]
[ 🚫 Деактивировать ] [ 🗑 Удалить* ]
[ 👥 Назначенные админы* ]
[ ← К списку ]
```
\* — только super_admin.

Обычный админ редактирует: имя, адрес, описание, фото, цикл, anchor.
Запрещены: смена `chain_name`, удаление, переназначение админов.

### 3.3 Создание магазина (визард)
> Только super_admin. Обычный админ кнопки «🆕 Добавить магазин» не видит.
Шаги в FSM `AddShopStates`: `name → address → chain → cycle → anchor → description → photo → assign_admins → confirm`.
- Сетки: подгружаются из `chains` (см. ниже), плюс «Независимый».
- На каждом шаге кнопки `Пропустить` и `Отмена`.
- `assign_admins`: мультиселект из списка обычных админов (можно никого; супер сам всегда имеет доступ).
- Финал: предпросмотр карточки → `✅ Создать` / `✖️ Отмена`.

### 3.4 Редактирование магазина
Каждое «✏️» открывает мини-флоу: показать текущее значение → попросить новое → сохранить → вернуть в карточку.
Изменения пишутся в `audit_log` (кто/когда/что/со старого на новое).

### 3.5 Удаление
- Двойное подтверждение (`Удалить?` → `Точно удалить?`).
- Если у магазина есть подписчики — предупреждение «N пользователей подписано, они потеряют подписку».
- Soft delete (`is_active=false` + флаг `deleted_at`); полное удаление — только super_admin.

### 3.6 Фото и галерея
- Хранение в Telegram (file_id), таблица `shop_photos(shop_id, file_id, ord, uploaded_by, uploaded_at)`.
- В карточке пользователя: первое фото как preview.

## 4. Раздел «Завозы и циклы»

> **Scope:** обычный админ работает только со своими магазинами.

### 4.1 Установка завоза
- Кнопка «📅 Установить завоз для магазина» → выбор магазина из scope → выбор даты (today / вручную / календарь).
- Кнопка «📅 Завоз для сети» — **только super_admin**. Выбор сети → дата → подтверждение `Применить ко всем N магазинам сети?`.

### 4.2 Календарь завозов
Экран на месяц вперёд: какие магазины когда завозятся (по anchor + cycle).
- Кнопки переключения месяцев `◀ Май 2026 ▶`.
- Клик по дате — список магазинов на этот день.

### 4.3 История завозов
Таблица `arrivals(shop_id, arrival_date, source enum('manual','parser','sheet'), set_by, set_at)`.
Раздел показывает последние 30 событий + фильтры по магазину/сети.

---

### 4.2 Календарь завозов
> Обычный админ видит только свои магазины в календаре.

## 5. Раздел «Пользователи»

> **Scope:** обычный админ видит только пользователей, у которых есть подписка хотя бы на один из его магазинов.

### 5.1 Список пользователей
- Поиск по `tg_id`, `@username`, имени.
- Колонки: tg_id, username, дата регистрации, число подписок, статус (`active`/`paused`/`blocked`).

### 5.2 Карточка пользователя
```
👤 @matvey  (5024046821)
Регистрация: 14.04.2026
Подписки: 5 магазинов
Уведомления: 09:00, не на паузе
Последняя активность: 04.05.2026 23:01

[ 📜 Подписки ]
[ ⏸ Поставить на паузу ]
[ 🚫 Заблокировать в боте ]
[ ✉️ Написать ЛС ]
```

### 5.3 Блок-лист
Таблица `user_blocks(tg_id, reason, blocked_by, blocked_at)`. Заблокированный пользователь получает заглушку при `/start` и не получает уведомлений.

### 5.4 ЛС от админа
Админ может отправить пользователю прямое сообщение от имени бота. Логируется в `admin_messages`.

## 6. Раздел «Рассылки»

### 6.1 Создание рассылки
Визард: `тип (текст/фото/документ) → контент → аудитория → расписание → подтверждение`.

Аудитории:
- `Все активные` — **только super_admin**
- `Подписанные на магазин X` — для admin: только его магазины
- `Подписанные на сеть X` — **только super_admin**
- `Подписанные хотя бы на один из моих магазинов` — для admin (скоуп-аудитория по умолчанию)
- `Зарегистрированные за последние N дней` — **только super_admin**
- `Кастомный сегмент` (импорт списка `tg_id` файлом) — **только super_admin**

Расписание:
- «Отправить сейчас»
- «Отправить в дату/время»
- «Отправить когда разблокируется» (если у юзера ночной mute)

### 6.2 Очередь и прогресс
Таблица `broadcasts(id, payload, audience_filter, scheduled_at, status, sent, failed, started_at, finished_at, created_by)`.
Экран «Активные рассылки» — прогресс-бар, кнопки `⏸ Пауза`, `✖️ Отмена`.

### 6.3 Антиспам и rate-limit
- Throttle 25 msg/sec, ретрай при `RetryAfter`.
- Если за 24ч было >2 рассылок — предупреждение «Высокая частота, точно отправить?».
- Опция «не слать тем, у кого пауза».

### 6.4 История и статистика рассылки
Доставлено/неудачно, разбивка по причинам (`forbidden`, `chat_not_found`, `flood`).

## 7. Раздел «Фидбек»

> **Scope:** обычный админ видит только фидбек, который пользователь оставил с привязкой к его магазину (`feedback.shop_id`), либо общий «без магазина» — только super.

### 7.1 Входящие
Список сообщений из `/feedback` пользователей: автор, текст, дата, статус (`new`, `in_progress`, `closed`).
- Кнопка `↩️ Ответить` — отправить ЛС автору от имени бота, ответ сохраняется в треде.
- Кнопка `📌 Закрыть` — пометить решённым.
- Поиск/фильтр по статусу.

### 7.2 Уведомления админам
Новый фидбек кидается в `ADMIN_CHAT_ID` (уже есть в `.env`) с inline-кнопками `Ответить` / `Закрыть`.

## 8. Раздел «Парсеры»

> **Scope:** обычный админ видит парсеры, которые относятся к сетям, где у него есть закреплённые магазины. Запуск парсера обновляет только магазины из его scope. Полный запуск по сети — только super.

### 8.1 Megahand
- «🔄 Запустить парсер сейчас» → результат: дата завоза, обновлено N магазинов.
- «📅 Расписание» — настройка частоты автозапуска (cron-выражение).
- «📜 Лог последних запусков» — статус, что нашли, ошибки.
- «🧪 Тест парсера» — dry-run без записи в БД.

### 8.2 Google Sheets (по аналогии со старой версией)
- Импорт магазинов из таблицы по `SHEET_ID`.
- Маппинг колонок настраивается в админке.
- Результат предпросмотра diff: «Будет добавлено: 3, обновлено: 12, удалено: 0» → `✅ Применить`.

### 8.3 Управление парсерами
- Включить/выключить каждый парсер.
- Указать `chain_name` для каждого парсера.

## 9. Раздел «Статистика»

> **Scope:** для обычного админа все цифры считаются по его магазинам и их подписчикам. У super-админа — глобально.

Текущая `/stats` остаётся как краткая сводка. Добавляем:

### 9.1 Дашборд
- Активных пользователей сегодня / неделя / месяц.
- Прирост пользователей (график ASCII или картинка через quickchart.io).
- Топ магазинов по подпискам / по кликам в каталоге.
- Воронка: `start → catalog → подписка → получил уведомление → открыл бот`.

### 9.2 Уведомления
- Сколько уведомлений отправлено за период.
- Failure rate.
- CTR: какой % уведомлений привёл к открытию бота в течение часа.

### 9.3 Экспорт
- «📤 Экспорт CSV»: пользователи / подписки / уведомления за период.
- «📤 Экспорт SQL-дампа» (только super_admin).

## 10. Супер-админка (роль `super_admin`)

Открывается по кнопке «🛡 Супер-админ» в админ-панели и `/sudo`.

### 10.1 Управление админами
- Список админов с ролью, кол-вом закреплённых магазинов, кто добавил, когда.
- `➕ Добавить админа` — ввод `tg_id` или forward сообщения от человека → выбор роли → (для `admin`) сразу выбор магазинов из мультиселекта.
- `📌 Назначить магазины` — для существующего админа: мультиселект всех магазинов с чекбоксами уже назначенных, `Сохранить`. Удаление назначения — снятием чекбокса.
- `🗑 Снять права` — двойное подтверждение, нельзя снять права с самого себя; при снятии все назначения удаляются (cascade).
- `🔁 Изменить роль`.

Карточка админа:
```
👤 @user (123456)
Роль: admin
Магазины: 3
  • Секонд №1 на Восставших
  • Секонд на Адм. Фадеева
  • Секонд на Острякова 60
Добавил: @super (250...)  04.05.2026
Заметка: «Куратор Megahand»

[ 📌 Магазины ] [ 🔁 Роль ] [ ✏️ Заметка ]
[ 🗑 Снять права ]
```

Просмотр «зеркалом» — `🔍 Открыть как этот админ»: супер открывает админскую панель в его scope (read-only), удобно для отладки прав.

### 10.2 Аудит-лог
Таблица `audit_log(id, ts, actor_tg_id, action, target_type, target_id, payload jsonb)`.
Логируется:
- любые изменения магазинов, чейнов, пользователей, прав
- запуск/остановка парсеров
- рассылки (старт/отмена)
- доступ к супер-админке
- изменения конфигурации

Экран: лента событий с фильтрами по `actor`, `action`, `target_type`, периоду. Поиск по `target_id`.

### 10.3 Управление сетями (`chains`)
Таблица `chains(id, name, default_cycle, parser_key, color, sort_order, is_active)`.
- CRUD сетей.
- Привязка парсера к сети.
- Дефолтный цикл — подставляется в визард создания магазина.

### 10.4 Конфигурация бота (рантайм)
Таблица `bot_config(key, value, type, updated_by, updated_at, description)`.
Переопределяет `.env` без перезапуска. Доступные ключи (примеры):
- `notifications.morning_time` (HH:MM)
- `notifications.evening_time`
- `throttling.callback_rate`
- `broadcast.rate_per_sec`
- `support_url`
- `sponsor_channel`, `sponsor_channel_url`
- `feature_flags.photos_enabled`
- `feature_flags.feedback_enabled`

UI: список ключей → клик → редактор по типу (`int`, `str`, `bool`, `time`, `url`).
Изменение немедленно перечитывается в коде через `config.live.get(key)` (тонкая обёртка с кешем 60 сек).

### 10.5 Управление БД
- `🧰 Резервная копия`: создать `pg_dump | gzip` в `backups/`, отправить файл в чат.
- `📥 Восстановить из бэкапа`: загрузить файл → подтверждение `Это сотрёт текущие данные. Точно?` → восстановление.
- `📊 Размер БД и таблиц`.
- `🧹 Очистка`:
  - удалить уведомления старше 90 дней,
  - удалить заблокированных пользователей без подписок,
  - vacuum.
- `🔧 SQL-консоль` (опционально, фича-флаг `superadmin.sql_console`): только `SELECT`, лимит 100 строк, тайм-аут 5 сек, в audit-лог пишется текст запроса.

### 10.6 Режим обслуживания
- Тогл `maintenance_mode = on/off`.
- При включении: все хендлеры (кроме админских) отвечают «🛠 Бот на обслуживании, попробуй позже».
- Можно задать сообщение и запланировать автовыключение через N минут.

### 10.7 Журнал ошибок
Текущий `handlers/errors.py` уже шлёт ошибки в `ADMIN_CHAT_ID`. Дополнительно:
- Таблица `error_log(id, ts, level, source, message, traceback, update_payload jsonb, resolved bool)`.
- Экран «🔥 Ошибки»: список, фильтр по дате/`source`, кнопка «✅ Помечено». Группировка по сигнатуре traceback (количество, last seen).

### 10.8 Перезапуск/диагностика
- `❤️ Health-check`: пинг БД, прокси, Telegram API, время ответа.
- `🔁 Перезапустить scheduler`.
- `🔁 Перечитать конфиг`.
- Полный рестарт процесса — только через systemd/Docker, в боте не делаем.

### 10.9 Импорт/экспорт магазинов в JSON
Полный дамп `shops + chains + photos` для переноса между окружениями.

## 11. Безопасность

- Все callback'и админки имеют префикс `adm:` / `sa:`. На уровне роутера — `IsAdmin` / `IsSuperAdmin`.
- Любой хендлер, работающий с конкретным магазином, проходит дополнительную проверку `IsAdminForShop(shop_id)`. Прямой доступ к чужому магазину по ручному `callback_data` отбивается с `«Нет доступа»` и пишется в `audit_log` с `action='access_denied'`.
- Никаких прав по `tg_id` из `.env` напрямую в хендлерах: только через таблицу `admins`. `.env` лишь сидит супер-админов на старте.
- Подтверждение для деструктивных действий (удаление, восстановление БД, рассылка >1000 человек, снятие прав).
- Rate-limit на админские callback'и (anti-doubleclick).
- Все деструктивные и привилегированные действия → `audit_log`.
- Экранирование HTML (`html.escape`) во всех местах вывода пользовательских данных.
- Длина ввода ограничена (имя ≤120, адрес ≤200, описание ≤2000).

```
handlers/
  admin/
    __init__.py        # router aggregation
```

## 13. UX-правила

- Все экраны умещаются в одно сообщение Telegram (≤4096 символов).
- Inline-кнопки сгруппированы: верх — данные/просмотр, середина — действия, низ — навигация.
- Длинные списки → пагинация (10/стр), номера через `1/N`.
- Деструктивные кнопки помечены `🗑`/`🚫`, всегда требуют подтверждения.
- Везде есть `← Назад` и `🏠 В меню`.
- Любой `edit_text` обёрнут в `safe_edit` (игнорим `message is not modified`).

## 14. Этапы (если делать поэтапно)

**MVP-1 (базовая админка):**
- Панель «Магазины»: список + карточка + создать/редактировать/удалить (3.1–3.5).
- «Завозы»: установка для магазина и сети (4.1).
- «Рассылки»: создание + аудитория «все», без расписания (6.1 частично).

**MVP-2 (расширение):**
- Фидбек-инбокс (7).
- Парсеры с UI (8).
- Календарь завозов (4.2), фото (3.6).
- Пользователи: поиск, карточка, блок-лист (5).
- Расписание рассылок (6.1, 6.2).

**MVP-3 (супер-админка):**
- Управление админами и аудит (10.1, 10.2).
- Рантайм-конфиг (10.4).
- Бэкап/restore БД (10.5).
- Режим обслуживания (10.6).
- Health-check, журнал ошибок (10.7, 10.8).
- Сети как отдельная сущность (10.3).

**MVP-4 (полировка):**
- SQL-консоль.
- Дашборды с графиками.
- Экспорты CSV/JSON.
- Тесты до 80% покрытия.

## 15. Acceptance criteria (короткий чеклист)

- [ ] Админ открывает панель кнопкой и `/admin`, видит только свои разделы.
- [ ] Супер-админ дополнительно видит «🛡 Супер-админ».
- [ ] Обычный админ видит только закреплённые за ним магазины во всех разделах (магазины, статистика, фидбек, рассылки, парсеры, пользователи).
- [ ] Попытка открыть чужой магазин по подделанному `callback_data` отбивается и пишется в `audit_log`.
- [ ] Супер-админ может назначать/снимать магазины с админа в один экран.
- [ ] CRUD магазинов работает целиком из кнопок, без слэш-команд.
- [ ] Любое деструктивное действие требует подтверждения и пишется в `audit_log`.
- [ ] Рассылка по сегменту корректно фильтрует и показывает прогресс.
- [ ] Парсер Megahand можно запустить из UI и увидеть лог.
- [ ] Изменение `bot_config` применяется в течение минуты без перезапуска.
- [ ] Бэкап БД скачивается в Telegram, восстановление работает на пустой БД.
- [ ] Режим обслуживания блокирует всех, кроме админов.
- [ ] Тесты проходят, нет необработанных `Unhandled exception` при тыкании всех кнопок.
